# Issue #43 — ingestion recovery and fault cleanup: design v2

**Status: proposed.** Base `origin/main@f701c73`; first local draft `872be01` (not pushed). The maintainer selected the six recommendations below as **design inputs**, not implementation approval. Require fresh independent design review and subsequent explicit maintainer acceptance before writing product code. V1 is superseded.

## Scope and decisions

Today ingestion faults retain only an error, not a retryable body, and terminal commit failure can leave a run nonterminal (`packages/runtime/README.md:7`). `startingRun`, `runs`, `turnAttempts`, pending commands and close facts split lifecycle ownership (`packages/runtime/src/runtime.ts:145-170,230-244`). Design one active `RunLifecycle` per run and one FIFO `SessionIngestion` per session, shared by session and run sinks. Store event, projection and receipt commits are atomic (`packages/runtime/src/store.ts:77-85,221-259`), but external provider and workspace effects are **not** crash-durable or exactly once. Issue #6 owns persistent claims, effect intents, orphan reconciliation, multi-process and crash recovery; this is one runtime instance only, with no wire/JSON Schema change.

Maintainer decisions (all six recommended options):

1. `retryProviderIngestion(sessionId?: SessionId)` targets a session or, absent ID, attempts **all** affected sessions in sorted order, continuing past individual failures.
2. Overflow does not prevent a successful **cleanup receipt** after accepted operations and actual cleanup commit; history stays permanently marked incomplete.
3. Exact close retry repeats only failed cleanup phases, not observed successes or in-flight calls, consistent with ADR-0005.
4. Keep one permanent fault marker per affected closed session for the lifetime of the runtime; never falsely certify replay.
5. An unresolved `startRun()` makes close/shutdown **promptly retryable**, not an indefinite wait. Fence it, mark its eventual handle for interrupt/dispose, and **do not release the workspace until provider disposal succeeds**. A never-settling provider can prevent eventual success but not block the caller forever.
6. Limit by **operation count (1,023)**, not retained bytes; explicitly disclaim a memory bound. Open a separate byte-budget follow-up coordinated with #19 durable storage; do not silently expand #19 or claim this follow-up is already filed.

## Ownership, ordering and terminal linearization

`RunLifecycle` is allocated **before** provider `startRun()`; it owns run/turn/attempt ID, phase (`S` starting, `R` running, `E` ending/fenced, `T` terminal intent/submitted, `X` retired), staged sink, start and receipt state, provider handle or pending start, supervision, interaction routes, unresolved command identities, terminal intent/submission and cleanup outcomes. `SessionIngestion` owns one ordinal allocator, FIFO of immutable operations **or effect reservations**, a single in-flight head, the accepted count, terminal slot, F/O faults, drain, current run, and session-level close/dispose/release state. It never copies per-run cleanup into parallel maps. At most one active or starting run exists per session. Retired run records are deleted after receipts, effects and cleanup settle; persisted receipts answer subsequent exact/conflicting retries.

`reserveStart`, `acceptEvent`, `reserveEffect`, `settleEffect`, `chooseTerminal`, `advanceHead`, `beginCleanup` and `retire` are the only mutating transitions. All provider callbacks capture/validate/clone/freeze synchronously before `emit()` returns. A stale retired-run callback is discarded **before** counting; a session-sink overflow targets the current active/starting run, not the old emitter. Session/run sinks and retained activation events share FIFO ordinals. A failed commit keeps its exact immutable head; a successful commit publishes then removes only that head. A blocked head blocks later **persistence**, new runs, `session.closed` and a successful close receipt in that session, but **not safe provider cleanup effects** or other sessions. Each failed attempt returns promptly; a proven pre-apply failure is retryable, while an ambiguous commit that cannot be reconciled fails closed rather than promising safe retry.

**Pre-effect reservation (P1).** After command/interaction validation and **before calling** `respondToInteraction`, reserve command ID, fingerprint, FIFO ordinal **and one capacity slot**. A pending provider call occupies that ordinal even if completion, close or overflow occurs. On success fill the same slot with response settlement + applied receipt; on definite rejection fill it with a rejected receipt, not a fictional response settlement. An ambiguous provider outcome is retained/reported retryable, not certified; a withdrawal has its own ordered slot and cannot displace an already delivered response. Exact retry shares the reserved identity; changed payload conflicts. Terminal selection may fence new input but must wait for all earlier reservations to settle; it cannot skip a response effect that reached the provider. If a provider response never settles, close/shutdown return a retryable failure rather than claim completion or wait indefinitely. Do not allocate a second slot when the reservation is filled (`packages/runtime/src/runtime.ts:981-1011,1493-1647`).

**Commit witness and terminal-written point (P1).** A transaction's atomic application is the actual commit point. Its promise can remain pending _after_ application (`packages/runtime/src/store.ts:178-259`). Before invoking `store.commit`, snapshot the owning session sequence; inside its synchronous transaction callback capture **every emitted envelope's `eventId` and `sequence`** (including ordinary text, interaction request/settlement, start, terminal, and close), or the command ID/fingerprint for receipt-only transactions. One ordinal owns one immutable bundle and one process-local published flag. Freeze terminal payload **before submission**; never rewrite a submitted/in-flight/acknowledged terminal. Overflow before submission may change an unsubmitted success intent to failed if truth permits; thereafter keep that outcome and mark O.

On commit fulfillment, publish its events once and advance the head. On rejection, synchronously set ambiguity guard **A before any reconciliation await**, wake live subscribers and block history assertions; do **not** resubmit blindly. Perform a read-after-failure of the authoritative store at the captured session/sequence, matching all event IDs and payloads (or `findReceipt` for receipt-only), including projection/sequence consistency. A full match means the transaction applied: publish those read-back envelopes **once** if not already published, finish its receipt, clear A for this head and advance. A provably absent bundle may be retried with its **same logical ordinal/body** only when the store contract guarantees that a settled rejection has no later application and a linearizable read sees every already-applied commit. A partial match, unavailable/stale read, non-atomic store, or unproven adapter guarantee leaves **A** permanent in this runtime: retain the head, surface nonretryable `store_unavailable` and require external reconciliation; never append another copy or certify history. `RuntimeStore` has no native idempotency token (`packages/runtime/src/store.ts:69-103`); #43 must document/enforce these minimum store assumptions before accepting a custom adapter, or explicitly reject auto-retry for that adapter. The current in-memory swap is atomic (`packages/runtime/src/store.ts:254-259`), but a custom injected store may apply then reject. This reconciliation applies to **all operation kinds**, not only terminals; extend A4 to `run.message_delta` and interaction request, proving no duplicate projection or live publish. #6 owns durable recovery beyond this process. Terminal bundles include pending-interaction cancellations, `run.finished` and `turn.settled` atomically; `turn.started` + `run.started` + submit receipt must precede them. Close and supervision cannot bypass the FIFO.

## Reachable transitions and fault precedence

F = recoverable retained-head failure; O = permanent incomplete-history overflow; **A = unknown store-commit outcome** awaiting reconciliation or permanently fail-closed if a safe decision cannot be established. A may coexist with F/O and any phase; A has highest query/retry priority, then O, then F. X has no accumulating per-run shell; session-only sink events remain possible when no run exists.

| Input                     | S: pending start/commit                                                                       | R                                   | E: fenced, waiting                                                                   | T: terminal reserved/submitted                          | X / no run                                                         |
| ------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------ |
| Event                     | stage/count                                                                                   | enqueue/count                       | only pre-fence accepted operations; invalid new interactions become diagnostics      | refuse fresh run input                                  | discard late run callback; session sink may overflow               |
| Overflow                  | O + fence, defer handle                                                                       | O + interrupt once                  | O; preserve earlier reservations                                                     | change unsubmitted intent only; never submitted payload | session-only O, no retired run to interrupt                        |
| Completion                | retain intent until start/earlier slots                                                       | fence/select                        | choose once after effect reservations                                                | ignore duplicate                                        | ignore late                                                        |
| Start commit OK / fail    | OK → R, or E/T if close/O/completion already requested; failed head retains same start bundle | N/A                                 | **reachable**: start+receipt commit first, then drain/terminal; failed head retained | must not submit terminal until start acknowledged       | rejected provider start: rejected submit receipt only, no terminal |
| Effect/withdrawal settles | fill prior reserved ordinal                                                                   | same                                | resolve reservation before terminal                                                  | prior unresolved reservation blocks submission          | pending old reservation may finish; refuse new effect              |
| Close/shutdown            | **fence ahead of session queue**, promptly retryable while start unresolved                   | interrupt/cleanup                   | retry only failed phases, no early release                                           | drain/commit before close receipt                       | replay receipt or finish session cleanup                           |
| Ingestion retry           | retry start head only when A absent                                                           | retry exact head only when A absent | drain then proven terminal if A absent                                               | retry unchanged terminal only when A absent             | retry pending receipt if A absent; O stays                         |

The old V1 `E/start commit OK` and `X/session-sink overflow` cells were incorrectly labelled impossible. A rejected `startRun` produces one rejected receipt, no start or terminal events. No successful close/terminal is fabricated from a timeout. At most one **invocation after an observed success** is assured; rejected/timed-out provider calls may have acted externally.

## Capacity, fault query, retry, subscriptions

The 1,023 **nonterminal-operation** cap includes in-flight head, staged and live session/run bodies, withdrawals, and pre-effect response/command reservations. Each filled reservation still counts once; one terminal bundle is separately reserved, as is fixed-size cleanup metadata. The pre-activation **256-event** limit is a guard **inside** the session budget, not another 256 uncounted slots. Crossing either cap refuses the excess before acceptance, retains the prefix, sets O permanently, fences fresh ingress/mutations, and interrupts current run when a handle exists. **Command-admission exception (maintainer decision, 2026-10-03):** a caller command or reservation (`reserveStart`, a response or other pre-effect reservation) refused because the session is at capacity does **not** set O: nothing is lost and the caller receives a retryable `capacity` error, so history stays complete. O is set only when provider-originated history is dropped. If session creation fails, discard unowned sink without ghost session marker. The former warning-only truncation changes accepted ADR-0016: its proposed update accompanies this plan. One arbitrarily large JSON body can still use much memory; byte budget is out of scope.

F remembers the first recoverably failing head with a saturating count; on successful drain it clears. O remains for runtime lifetime even after close, occupying one marker per affected session. A is set _before awaiting_ reconciliation after a rejected/uncertain commit. A clears only after proof of full application or provable absence under the strong settled-rejection + linearizable-read adapter contract. If proof is impossible, A retains one small witness/fingerprint and head for the runtime lifetime, even after safe cleanup; it cannot be cleared by close or shutdown. Query returns **one entry per session, A > O > F**: A/O use existing `store_unavailable`, `retryable: false` with distinguishable public message, F-only is `retryable: true`. This retains the maintainer's F+O → O decision while never making A appear retryable. `retryProviderIngestion` with A returns nonretryable `store_unavailable` **without resubmitting the head**; with F+O and no A an attempted retry reports recoverable F while its head fails, then nonretryable O after it clears. Unknown session returns `unknown_session`, healthy session no-ops. Retry of O still drains earlier accepted bodies, but never declares recovery while O remains. Global retry attempts all, reports failed session IDs deterministically, and never reissues provider/workspace effects. Concurrent retries share a session drain; each failed attempt releases its retry lock. Safe provider cleanup can proceed despite A as with F, but a successful terminal/close receipt cannot bypass its head.

`readEvents`, replaying subscriptions and `quiesce` reject while **A, F or O** exists. Check before/after each store page (`packages/runtime/src/runtime.ts:2036-2055`). Use a **module-internal notifier** (not a required member of the public `SubscriptionHub` type exported via `packages/runtime/src/index.ts:28`) to wake already-live subscribers blocked after `caught_up`, and check fault before delivering a buffered event, after each wake and before `closed`; their next `next()` rejects, rather than hanging or yielding a healthy-looking closed marker (`packages/runtime/src/subscriptions.ts:51-65,165-205,222-274`). Notify at first A/F/O transition, _before_ reconciliation I/O; a held read must not let an idle subscriber wait indefinitely or deliver a healthy-looking page. This is separate from subscriber delivery-buffer overflow. A close receipt only attests actual cleanup; it does not clear O or attest complete history.

## Pending start, cleanup, retirement, shutdown

Currently `startRun()` waits inside the session queue, which makes close/shutdown wait too (`packages/runtime/src/runtime.ts:265-270,1305-1313,2063-2117`). Close/shutdown must fence/admit outside that queue and **must not await its unresolved tail**. A close with `ifRunActive: reject` retains its existing rejection policy for a starting run. For `interrupt`, first reserve the close ID/fingerprint and first-acceptance facts, then fence the start synchronously. A second close ID while unresolved is refused; exact ID retries share the intent, changed payload conflicts. If no handle yet, close returns retryable `provider_unavailable` immediately (no rejected-command receipt). Shutdown synchronously closes admission, attempts other sessions and rollbacks, reports the blocked session as retryable and remains retryable; no success, subscription close or false lease release. All pending start/effect promises have fulfillment **and** rejection handlers to prevent unhandled rejections.

If the late start **rejects**, discard only that run's provisional staged operations and release their charged slots; no start/terminal event exists. An O caused only by those unowned run events rolls back, while independent session-sink O/F persists. The rejected submit receipt keeps its original command identity/position. Attempt provider-session disposal even if F blocks that receipt. If it **resolves**, do not activate a new run: quarantine the handle, attempt interrupt once and dispose as soon as provider use has settled, **regardless of persistence F**. Its start+submit receipt must eventually commit ahead of its captured run events and terminal, but that write is NOT a prerequisite for safe provider cleanup. A successful interrupt or disposal supplies truthful fallback proof. No runtime timeout is invented: a never-settling start keeps one fenced record and lease; each explicit close/shutdown promptly returns retryable failure.

Close attempts safe independent cleanup work even if interrupt fails; retain phase-tagged failures. **Disposal depends on no still-pending provider start or response use; release depends on confirmed successful provider disposal, NOT on FIFO persistence.** Once disposal succeeds, attempt lease release even if F/A blocks accepted history or terminal; neither effect implies a successful close receipt. This refines ADR-0005's existing attempt-all rule so a provider can never use an already released workspace. Retry only failed phases, never observed successful or in-flight calls. **Canonical partial order, not unconditional closing-before-terminal:** a successful `turn.started` + `run.started` + submit receipt precedes captured run bodies and earlier response reservations in ordinal order (projection requires `ready` at start, `packages/runtime/src/projection.ts:103`). If **close selects an as-yet-unsubmitted terminal**, enqueue `session.state_changed → closing` after the start/earlier accepted ordinals and _before_ submitting that terminal. If a completion/overflow terminal was **already submitted or committed** before close admission, preserve its frozen FIFO position and outcome; enqueue `closing` _after_ that terminal (even if its acknowledgment is still pending). Never insert closing ahead of submitted events, never resubmit a terminal, and never append a new run body after the terminal. In either case `session.closed` and close receipt follow the terminal, closing, and real disposal/release. The admission fence may precede all commits, and cleanup effects may proceed while F/A blocks them; none may reorder the log. A rejected start discards its unowned staging instead of appending a nonexistent run. A failed receipt commit retains intent/release report, not the effects. `interruptedActiveRun` accumulates truth across exact retries. Cleanup receipt after O succeeds only after disposal, release, accepted prefix and terminal/close commit; O persists.

After receipts commit, delete retired `RunLifecycle`, `turnAttempts` (`packages/runtime/src/runtime.ts:164,1299-1302`), routes, withdrawals, sinks, supervision, pending commands and command-attempt fingerprints. An unresolved receipt retains **one minimal tombstone** (ID, fingerprint, acceptedAt, body/ordinal), then is deleted after commit; a stale sink holds at most a small immutable retirement fence, never a body/handle or growing session map. Many successful turns in a long-lived session must consume constant _active_ run bookkeeping. A single never-settling start/effect is an explicit bounded-count liveness exception. Closed sessions may retain one O marker. Shutdown succeeds only after all required cleanup and commits, then closes subscriptions; O alone does not prevent cleanup success, though history remains untrustworthy.

## API, docs and implementation acceptance

Add required `AgentRuntime.retryProviderIngestion(sessionId?: SessionId): Promise<void>` (`packages/runtime/src/index.ts:8-13`). **Breaking TypeScript change** for consumer-defined structural `AgentRuntime` objects: pre-1.0 changeset remains `minor`, but its body **begins `BREAKING:`**, telling custom implementers to add the method (or use `createAgentRuntime`). No new wire schema/code. Add packed consumer compile proof in implementation; docs-only design needs **no** changeset. Update README's old failure/close wording when behavior actually changes. The proposed ADR-0016 and ADR-0005 amendments must be accepted together with this design; until implementation current ADR behavior remains documented as current. The retained terms `command claim`, `ingestion ordinal`, `terminal intent`, `cleanup intent/outcome`, and `retirement fence` are future #6 durability seams, not a durability claim today.

Deterministic acceptance tests use deferred store/provider promises and direct state/event/receipt inspection; **no 200 ms bound, sleeps, or timing-sensitive assertions**:

- A1: fail accepted body/terminal commit; retry preserves immutable bodies, starts before finishes exactly once, and close/shutdown cannot succeed early; rejected start has no start/terminal.
- A2: interleave session/run sinks; a blocked head stalls only its session and retry returns immediately with F; 1,024 tiny operations at a blocked head retain at most 1,023 plus terminal, with no elapsed-time test; a large body demonstrates count-only cap.
- A3: defer response; race completion, close, withdrawal and overflow; reservation precedes terminal and does not lose provider-delivered response or accept it after delivery only to reject its slot; definite rejection fills same slot with rejected receipt.
- A4: overflow before terminal submission may change intent; after submission and after transaction application it cannot rewrite outcome, even while response is held. Apply-then-reject and pre-apply-reject fixtures for **ordinary `run.message_delta`, interaction request, terminal and receipt-only** heads; prove one stored projection effect, one published live event, or fail-closed uncertainty. An unsupported adapter whose outer promise rejects _before_ its underlying delayed write then returns empty on immediate read must retain A, reject replay/subscriptions, and **never resubmit** when the delayed write later applies; hold a reconciliation read and assert A/wakeup is already visible before it resolves. Do not confuse a wrapper that throws before the state swap with apply-then-reject. With a submitted completion terminal whose acknowledgment is held, admit close: prove one original terminal, `closing` ordered **after** it, and a truthful eventual close receipt.
- A5: never-settling start makes close and shutdown **return** retryable results under controlled scheduling, not wait for start; no release. Late success with a **permanently rejecting store head** still interrupts/disposes/releases without a false close receipt; late rejection discards only run staging, eventually records rejected submit without terminal and disposes/releases. Verify closing state is not committed before a successful delayed start. `ifRunActive: reject` stays truthful.
- A6: overflow through session sink during pending start targets current run; late retired sink takes no slot; 256 activation overflow permanently marks O.
- A7: idle live subscriber after `caught_up` wakes on A/F/O and rejects. With F+O fault query returns O; A+O+F returns A and no retry can resubmit A's head. Retry reports F while a recoverable head fails, O after drain. Reads/replay/quiesce reject after close when any fault remains.
- A8: after O close/shutdown return **truthful successful cleanup** receipts when cleanup/accepted commits succeed while O remains. Fail interrupt, dispose and release separately; retry only failed phases and never release before dispose.
- A9: failed submit receipt + close does not revive effect on retry; many successful turns clean `turnAttempts` and retired records; only unresolved tombstones remain; new close IDs do not grow leaked fingerprints.
- A10: exact README/ADR-0016/ADR-0005 and breaking changeset wording/consumer proof, focused runtime/executor tests, typecheck, `pnpm skills:check`, `pnpm gate`, and `git diff --check` for the eventual implementation. These are **future gates**, not evidence that implementation was tested now.

## Four separately reviewable implementation surfaces (only after approval)

1. State reducer, reservation/FIFO ordering and transition proof (shadow mode; no claimed behavior fix).
2. Event ingress, activation, caps and fault wake; remove old ingress bypass at the atomic cutover.
3. Terminal submission, start ownership, response/withdrawal settlement and immutable retries; no direct terminal bypass.
4. Cleanup integration (fail-fast pending start, delayed handle, dispose-before-release, retirement), public retry, README/changeset and packed consumer.

Each requires focused tests/typecheck and `pnpm gate` before review. If separate PRs would leave an observable bypass, keep changes local and integrate at a dependency-safe point while still reviewing the four surfaces separately. **No product code, remote push/PR, or implementation writer before fresh design review and explicit maintainer approval.**
