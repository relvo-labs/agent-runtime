# Issue #43 design: ingestion recovery, overflow, and fault cleanup

Base: `origin/main` `f701c73`. Scope: process-local runtime behavior aligned with issue #6.

## Problem and goal

The current runtime reports provider ingestion failures but retains no failed event body for retry; a failed terminal commit can leave a stored run non-terminal (`packages/runtime/README.md:7`). Run ownership is split among `startingRun`, `runs`, fences, supervision, pending submits, command attempts, and close facts (`packages/runtime/src/runtime.ts:145-170`, `packages/runtime/src/runtime.ts:230-244`); provider event commits and terminal commits take separate paths (`packages/runtime/src/runtime.ts:864-875`, `packages/runtime/src/runtime.ts:934-1089`), while close can terminalize directly (`packages/runtime/src/runtime.ts:1806-1848`). The goal is one ordered, bounded, retryable process-local lifecycle that preserves accepted events, produces truthful terminal state and receipts, and completes cleanup once. Non-goals: crash durability, provider resume, external exactly-once effects, and wire/JSON Schema changes. A proposed wire change requires a separate maintainer decision.

## Ownership and transitions

One `RunLifecycle` record is allocated **before** `startRun()` and retained through retirement. A `SessionIngestion` owns one FIFO across session-sink and run-sink operations; a session has at most one active or starting run. These are runtime-private records, not DTOs.

| Record             | Fields and ownership                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RunLifecycle`     | `sessionId`, `runId`, `turnId`, `attempt`, `phase`, `ingressFence` (`none/interactionOnly/all`), `startCommitted`, `providerRun?`, staged sink, supervision stop, interaction routes/withdrawals, `terminalIntent?` (chosen outcome and time, source, truth proof), `cleanup` (interrupt/dispose/release outcome and in-flight promise, release report), `submit` (command, fingerprint, acceptedAt, pending receipt or rejection), `closeIntent?` (fingerprint, acceptedAt, cumulative `interruptedActiveRun`), and `retired` fence. It owns run-scoped interrupt/response fingerprints. Session cleanup uses this active run's fields; after retirement, the same record remains a small shell until close settles. |
| `SessionIngestion` | `sessionId`, FIFO of immutable operations `{ordinal, ownerRunId?, kind, capturedValue, apply}`, one in-flight head, accepted-body count, reserved terminal slot, first retryable fault, permanent overflow fault?, bounded failure count, drain promise, and `activeOrStartingRunId?`. With no run, this record owns the session-only close intent and dispose/release outcomes. It never has a second copy of an active run's cleanup state.                                                                                                                                                                                                                                                                         |

`reserveStart`, `acceptEvent`, `chooseTerminal`, `advanceHead`, `beginCleanup`, and `retire` are the only state-changing transition functions. Commands, provider callbacks, supervision, overflow, close, shutdown, and ingestion retry call these functions. Provider callbacks synchronously capture and enqueue values before returning; a terminal signal synchronously fences further ingress. A successful store commit removes **only** the FIFO head after publish; a failed commit leaves that exact immutable head in place. `chooseTerminal` appends one terminal bundle after every accepted earlier operation (including retained response/withdrawal settlement); its bundle commits interaction cancellations, `run.finished`, and `turn.settled` atomically. No direct close or supervision terminal commit bypasses this queue. Store commits already append events, fold projections, and record receipts atomically (`packages/runtime/src/store.ts:77-85`, `packages/runtime/src/store.ts:221-259`); this design does not infer provider or workspace exactly-once from that fact.

### State machine

Cells are `next phase / permitted effect`. `S` = starting (`startRun` or start commit pending), `R` = running, `E` = ending (fenced; truthful terminal proof pending), `T` = terminal queued (proof known; FIFO predecessors may remain), `X` = retired. `F` is a queue fault flag orthogonal to phase; `O` is permanent overflow. `same` means phase unchanged. `—` means impossible by transition guard and must assert in tests. A store commit result applies only to its head; start and terminal results are distinguished in the cell. A late callback from `X` or another run is discarded before it consumes capacity.

| Event                     | S                                                                              | R                                                     | E                                                                                        | T                                                                         | X                                                                   |

| Overflow                  | E+O / fence; wait for handle, then interrupt                                   | E+O / fence, request interrupt once                   | E+O / retain proof attempt                                                               | T+O / retain terminal, make outcome failed if still uncommitted           | X / impossible; stale ingress discarded                             |
| Provider terminal signal  | E / retain outcome until start commits                                         | T / fence, choose terminal                            | T / choose once if no stronger overflow intent                                           | T / ignore duplicate                                                      | X / ignore late signal                                              |
| Interrupt result          | E / record once if handle exists                                               | E / record once; ordinary interrupt awaits completion | E or T / success proves close or overflow fallback; failure awaits completion or dispose | T / retain result only                                                    | X / ignore late result                                              |
| Dispose result            | S or E / only after a handle; success proves provider stopped                  | — / cleanup first enters E                            | E or T / record result; success proves fallback                                          | T / record result                                                         | X / no new call                                                     |
| Store commit OK           | R / start+submit receipt; activate staged FIFO, or X on rejected start receipt | R / dequeue head                                      | E / dequeue nonterminal head                                                             | T or X / dequeue head; terminal success retires after receipt obligations | X / settle pending rejection or close receipt; else —               |

| Exact `submit_turn` retry | S / finish retained start or rejection; no second start                        | R / replay stored receipt                             | E / replay receipt or finish retained start if still S-owned                             | T / replay receipt; no revival                                            | X / replay stored receipt or finish retained rejection; never start |
| Conflicting retry         | same / `command_id_conflict`                                                   | same / conflict                                       | same / conflict                                                                          | same / conflict                                                           | X / conflict from receipt or unresolved tombstone                   |
| Close                     | E / fence, await start, then cleanup                                           | E / fence, interrupt once, cleanup                    | E or T / resume incomplete cleanup                                                       | T / drain then receipt                                                    | X / receipt replay or session close                                 |
| Shutdown                  | E / same as close after admitted commands drain                                | E / same as close                                     | E or T / retry cleanup                                                                   | T / drain then close                                                      | X / release session bookkeeping                                     |
| Ingestion retry           | S / retry start head                                                           | R / retry FIFO head                                   | E / retry FIFO head, then terminal when proved                                           | T or X / retry FIFO through terminal                                      | X / retry pending receipt, else no work; O still faults             |

The `S`/terminal and `S`/dispose cells require a start result: if `startRun()` rejects, commit the retained rejection and retire with **no** `run.started` or terminal; if a handle arrives, finish the start transaction before any terminal bundle. `R`/close cannot choose a terminal until interrupt succeeds, provider completion arrives, or dispose succeeds. A user `interrupt_run` success alone keeps `E` until completion or close fallback. In `T+O`, any uncommitted provider success is replaced by a failed overflow outcome; a committed terminal is never rewritten.

## Invariants

1. `run.finished` has one committed `run.started` owner; each committed start eventually has exactly one terminal once the store recovers or cleanup supplies truthful proof. A permanently failing store remains visibly pending, never silently terminal.
2. The terminal bundle is the **last retained operation for its run**. It commits only after every earlier accepted run operation and any side-effect-derived settlement commit; no accepted event is dropped because a later terminal projection exists.
3. One session FIFO preserves synchronous capture order across both sinks and completion. Head commit failure retains its body and ordinal; retry never reissues its provider effect or duplicates a committed event.
4. `interrupt`, `dispose`, and `release` each have one in-flight invocation and at most one **successful effect** per lifecycle; their in-flight and successful outcomes survive command, close, shutdown, and ingestion retries. A successful call is never repeated. An observed failure may be retried only through explicit cleanup retry on the same record, as ADR-0005 requires; a failed interrupt may instead use successful disposal as terminal proof. No store-commit retry invokes any of them.
5. Overflow always targets `activeOrStartingRunId` selected from session ownership, never the emitting event's possibly stale run ID. The record exists before `startRun()` awaits; stale callbacks consume no capacity.
6. A refused provider body sets permanent `O` for that session in this runtime instance. Retrying retained bodies cannot restore complete replay; `readEvents`, replay subscription, and `quiesce` continue to reject.
7. Retirement is monotonic. An exact pending submit retry can only finish a stored rejection or replay a committed receipt; neither a retired run nor a closed session can call `startRun()` again.
8. Retired records release sink, handle, supervision stop, interaction routes, withdrawals, queue bodies, and settled fingerprints. Unreceipted identities retain only bounded tombstones until their receipt commits; fresh close IDs after fault cleanup create no new in-memory fingerprints.
9. Per-session accepted ingestion is at most 1,023 nonterminal bodies plus one reserved terminal bundle, counting in-flight and staged bodies. Faults are O(1) per affected session; fingerprints are bounded by commands admitted before a fault plus one active close intent. While faulted, fresh mutations are rejected before reservation. Failure counts saturate, and no promise rejection is unhandled.
10. Close success requires provider disposal, workspace release, committed terminal for each committed start, drained accepted ingestion, and a committed close receipt. Shutdown success requires the same for every session and rollback, plus subscription closure.

## Overflow policy and targeting

Use 1,023 accepted nonterminal operations per session plus one reserved terminal bundle. The cap covers the existing 400-event reference burst noted in the prior attempt while leaving a finite budget for a stalled store; the existing pre-activation sink separately caps at 256 (`packages/runtime/src/runtime.ts:638`, `packages/runtime/src/runtime.ts:877-925`). Count the queue head in flight, staged bodies, session-sink bodies, and side-effect-derived settlements against the same cap. No operation may bypass the cap by being moved between staging and FIFO. On the first attempted body beyond the cap, refuse it, set `O`, fence both sinks, and reject new work for that session. Terminal and cleanup metadata use fixed reserved slots and do not depend on body capacity.

| Session ownership at refusal | Target/action                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start in flight, no handle   | `activeOrStartingRunId` already names `S`; mark `O`, await the original start result, then interrupt the returned handle once or retire a rejected start.     |
| Handle/start commit pending  | Same `S` record; hold terminal until start commits; interrupt once when possible.                                                                             |
| Running or ending            | Current `R/E/T` record, even if a late old-run sink caused pressure; request one interrupt, with successful dispose or provider completion as fallback proof. |
| No active/starting run       | No run target; fence session ingress, drain accepted session operations, then allow cleanup.                                                                  |

An old-run callback after retirement is discarded **before** capacity accounting. If overflow occurs from an accepted session-sink body while another run is active, that actual run is targeted. `O` remains queryable after all accepted bodies drain and after close/shutdown; replay cannot claim a complete log. Ordinary pre-activation excess should also set `O` rather than emit a diagnostic claiming only a recoverable tail loss. Existing subscription overflow is a distinct, cursor-based delivery condition (`packages/runtime/src/subscriptions.ts:92-110`, `packages/runtime/src/subscriptions.ts:238-254`).

## Retry, reads, and cleanup

Add `retryProviderIngestion(sessionId?: SessionId): Promise<void>`. It serializes with the named session FIFO; omitted ID retries faulted sessions in stable session-ID order. An unknown explicit ID rejects `unknown_session`; a known healthy session is a no-op. This method remains available during failed shutdown so a retained terminal can finish. Concurrent calls share each session's drain promise. It retries retained heads in ordinal order, then a proven terminal bundle, then any pending close commit. It never calls provider/workspace effects. A continued store failure leaves the same head, increments a saturating fault count, rejects with retryable `store_unavailable`, and permits later retry; other sessions can progress. A drained transient fault clears only after its full accepted prefix and terminal commit. `O` never clears and makes this API reject even when the queue drains.

`quiesce()` rejects if any session has `F` or `O`; it may resolve only after tracked ingestion drains. `readEvents(sessionId)` and replaying subscriptions reject for that session before and after store reads; a live subscriber already receiving events must have its iterator reject with `AgentRuntimeError` on a newly observed ingestion fault rather than emit `caught_up` or a complete cursor. Current replay checks bracket store pages (`packages/runtime/src/runtime.ts:2036-2055`, `packages/runtime/src/subscriptions.ts:165-205`); preserve that boundary. `getProviderIngestionFaults()` keeps its exported shape and reports one bounded first fault per session (`packages/runtime/src/runtime.ts:90-103`, `packages/runtime/src/runtime.ts:296-340`). A closed session with `O` retains one fault marker for the lifetime of this runtime instance; O(number of affected sessions) is unavoidable without durable fault storage or forgetting the replay guarantee.

Close first fences ingress and reserves its logical command, then waits for an admitted start result, requests run interruption once, attempts provider disposal and workspace release once each **even if an earlier phase fails**, and drains accepted ingestion. If a cleanup call rejects, exact close retry retries only that failed phase; successful or in-flight phases are never redelivered. A successful interrupt, successful dispose, or truthful provider completion permits terminal selection; terminal waits behind accepted events and start. Commit `session.closed` and the close receipt only after terminal and accepted-prefix commits and both cleanup successes. If cleanup succeeded but the store still fails, retain the close intent and release report; exact close retry or ingestion retry repeats only commits. An already accepted close ID retains its original `interruptedActiveRun` fact and acceptance time; a changed payload conflicts. A new close ID during an unresolved close/fault cleanup receives a retryable error without reservation, preventing unbounded fingerprints. A successful close receipt describes cleanup, **not** complete replay if `O` remains; reads still reject. This preserves ADR-0005's cleanup/receipt distinction. Current close already attempts dispose and release separately (`packages/runtime/src/runtime.ts:1751-1804`) and records a close receipt with `interruptedActiveRun` (`packages/runtime/src/runtime.ts:1865-1882`), but its direct terminal commit must move behind ingestion.

Shutdown closes admission synchronously, drains admitted commands, uses the same session transition and cleanup state without a synthetic caller receipt, and remains retryable after failure. It rejects while any terminal, accepted head, close commit, or cleanup failure remains; it closes subscriptions only on success. Current shutdown already memoizes an attempt and retries after rejection (`packages/runtime/src/runtime.ts:2063-2117`). A terminal commit failure therefore leaves the stored run non-terminal **and** retains its exact terminal bundle until retry succeeds; cleanup side effects can already be finished without a false shutdown success.

Names that should survive issue #6 are **command claim**, **ingestion ordinal**, **terminal intent**, **cleanup intent/outcome**, and **retirement fence**. They define a future store transaction boundary: persist claim and effect intent before provider/workspace side effects, then atomically record event/projection/receipt and reconciled outcome. This issue's records and once-flags are memory only; they do not survive crash, arbitrate multiple processes, discover orphan handles, or enable resume. Issue #6 owns durable claim/intent storage, single-writer admission, orphan reconciliation, adapter recovery compatibility, and crash testing. In-memory atomic event commits alone do not provide external exactly-once effects (`packages/runtime/src/store.ts:159-170`, `packages/runtime/src/store.ts:254-259`).

## Deterministic test plan

Use deferred promises for store commit, `startRun`, completion, interrupt, dispose, and release. Advance only by resolving a named deferred and awaiting its exposed operation; no timers, tick loops, or `setImmediate`. Instrument one invocation counter per effect, queue head/ordinal diagnostic, and store event page. Finding 4 reported a timer-based cleanup test in an earlier review; keep its replacement deterministic even though this base has no such assertion.
